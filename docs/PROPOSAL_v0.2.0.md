Step 2 の (⊇) 方向 `N⁻(v) ⊆ N⁺⁺(v)` は、**同時に強連結性も配達する**

`|N⁺⁺(v)| ≤ 16−8 = 8 = |N⁺(v)|` すなわち (⊆) 方向(`m(v) ≤ 0`、上界 ≤17)まで到達しており、

監修所見 §9.3 に対応表が記録されている。README 改訂案の T8 行の Remark はこれを出所とする。

### 差し戻し: T9 正文の「n < 24 では族が空」は**偽**

内部 §11.8 の訂正2 由来の文であり、**どの受理済み SHOKEN も通っていない**
(`SHOKEN_2026-07-25_bound_B.md` に該当記述はない)。私はそれを正文として引き写した。

**反例**(監修が提示、依頼側でも公開検証器で独立確認):
商 H = 5頂点巡回トーナメント `C₅(1,2)`(各頂点の H 内出次数 2)、全クラスサイズ 4、cap 0。
各クラスの出次数和は 4+4 = **8**。

```
n = 20 | excess 20, min_out_degree 8, strongly_connected True
```

→ **n = 20 の族メンバーが実在する。** 空ではない。

**誤りの機構**: m = 3(有向三角形)では H の各頂点の出次数が 1 なので
`δ⁺ ≥ 8` は**各クラスが 8 以上**を強制し n ≥ 24 が出る。

**m=3 でのみ正しい論法を族全体に外挿した**のが原因。
発生源は逆解きの「可行例の min n = 24」(これは **excess ≤ 3 が可行**な最小 n)を
**族メンバーシップの min n** と読み替えたことと推定される(監修の推定に依頼側も同意)。

**主命題2つは生きている。** 監修が n = 20〜23 で **633,125 メンバー**を掃引し、
`excess ≥ 3` の違反 0 件、`3∤n` で `excess = 3` のもの 0 件。壊れたのは空虚性の注釈だけ。

**修正済み**: README 改訂案から当該文を削除し、代わりに
(a) 主張は n に上限を持たず持つ必要もない、(b) **族は n < 24 で空ではない**(n=20 の実例)、

## 2. 問題1: "floor" の語法 — 対処方針

**枠組み: これは「新しい知見による更新」ではなく「自リポジトリの規約に本文が
追従していない状態の是正」である。** 公開リポジトリ `CLAUDE.md` の検証プロトコル節に

> 探索到達値は上界であり floor ではない (negative-control 教訓)

が**v0.1.0 の時点で既に書かれていた**。ところが同じリポジトリの `README.md` 本文は
測定値を "the measured floor" と 7 箇所で呼び続けていた。規約は自分たちのもので、
今日の改善は**それが破れていたことを可視化した**にすぎない。

この枠組みは正確であるだけでなく、正典 §3 の乖離ゲートの一般形でもある
(散文 vs 実行されるコード → 散文 vs 自分で書いた規約)。改訂案では
README の用語節の冒頭に上記の規約文を引用し、以後本文が規約から離れられないようにした。

対処は、語を1つ禁止するのではなく **3語を定義して使い分ける表を README 冒頭に置く**。
選択肢を減らし、以後の判断を機械的にするため。

| 語 | 意味 | 証拠としての価値 |
|---|---|---|
| **floor** | E_δ(n) そのもの(厳密な最小値) | **n ≥ 18 のどの n でも未知。** n=17 は 17(T8) |
